# Stitch Screen Briefs

## Landing
- **Purpose:** explain the product and start an analysis.
- **Required:** product promise, CTA to input, methodology/engine discovery, truthful capability preview.
- **Constraint:** no session required; no claims of live data, AI, recommendations or unsupported features.

## Financial Input
- **Purpose:** collect and validate exactly three annual periods.
- **Required:** demo load, company context, six navigable steps, all financial fields, visible labels, plain-number guidance, three-period view, local draft state, validation review and Analyse action.
- **Constraint:** one form; strings until explicit transform; warnings nonblocking; no input for company id.

## Executive Dashboard
- **Purpose:** explain company condition in about 30 seconds.
- **Required:** current/prior/currency/coverage context; score/band/change/trend; diagnosis; six KPIs; five dimensions; principal strengths/risks; charts/table/evidence.
- **Constraint:** content originates in analysis view model; score unavailable is explicit; no generic AI commentary.

## Ratio Analysis
- **Purpose:** inspect every formula-registry ratio and selected trend.
- **Required:** context, category/metric selection, current/prior/delta, formula/interpretation/availability, grouped table.
- **Constraint:** no raw ids; local table scroll; unavailable never zero.

## DuPont Analysis
- **Purpose:** explain ROE as Margin × Turnover × Leverage across periods.
- **Required:** current/prior ROE, identity/reconciliation, factor comparison, Shapley contributions in percentage points, trend/index disclosure, deterministic explanation, methodology.
- **Constraint:** identity and attribution checks are distinct; no hidden residual; leverage is contextual.

## Scenario Lab
- **Purpose:** compare immutable Base Case with a transformed latest-period statement case.
- **Required:** context, base/preset/custom controls, complete assumptions, score/dimension/metric/insight/DuPont comparisons, limitations.
- **Constraint:** scenarios are not forecasts; no direct score or ratio editing; errors are distinct.

## Engine Map
- **Purpose:** explain real pipeline and ownership.
- **Required:** stages, selectable inspector, provenance, consumers, scenario reuse, principles, technical detail.
- **Constraint:** existing metadata is authoritative; no company session required and no fictional nodes.

## Methodology and safe states
- **Methodology:** formulas, scoring limits, disclaimer, coverage and scenario limitations.
- **Safe states:** loading, no session, corrupt session, canonical invalidity, calculation failure, unavailable results, invalid scenario; always offer a clear recovery route and never retain stale data.
